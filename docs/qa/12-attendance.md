| AT-04 | note | **Installing the plugin changes payslip proration.** From the moment `attendances` is installed, payroll uses each employee's real working days (their calendar, else the company's, else the lowest-id company-less calendar — the seeded default Mon–Fri 08–17 counts) instead of the fixed 22, **whatever the three toggles say**. | AT-05 | note | The three payroll toggles (deduct absence / deduct lateness / pay overtime) all start **off**. Lateness is a per-minute deduction (`late minutes ÷ 60 × basic ÷ working days ÷ shift hours`); overtime is paid from **approved** requests only, at the multiplier stored on each request. Overtime earnings are not insurable for PASI and do not feed percent-of-gross components. Generate or recalculate a month's payroll batch **after** the month has been closed by the nightly job (from the 1st of the next month, after the night run, or run `php artisan attendance:close-day --date=...` for the remaining days); a batch generated earlier only sees attendance up to yesterday and later absences are never deducted (validated payslips are not rebuilt). | by design |
| AT-06 | note | The device user id is the employee's existing **barcode** field (labelled "Attendance device user ID" on the employee form). Ids shared by two employees are listed as ambiguous and never guessed; leading zeros in numeric XLSX cells are lost (the id then shows as unmatched). Re-importing the same file creates no new punches. Slash dates are read day-first (dd/mm/yyyy); device times are read in the company time zone. A realistic monthly export for ~30 employees imports in seconds; for hundreds of employees import one week at a time (the import runs in one web request). | by design |
| AT-07 | note | Day rules: first punch = in, last = out; lunch rows of the calendar are not worked time; lateness after the 10-minute grace; overtime only above the minimum (30 min) and always starts as a **pending request** (decided requests are never changed by recalculation). A lone punch after the shift midpoint is treated as a missing check-in (no lateness). Employees with the "flexible" flag get no lateness. Employees with no calendar: attendance is informational (no absence/lateness/overtime request). Calendar rows tagged with a display type (Working/Off/Holiday) are ignored by the schedule, like the existing calendar code does. Manually typed overtime for an employee without a calendar can be approved but payroll pays nothing (no schedule). | by design |
| AT-08 | note | Absence needs the nightly job: add the cron `* * * * * php artisan schedule:run` (already required). The job closes **yesterday** (so today's absence is recorded tomorrow); a missed night is repaired with `php artisan attendance:close-day --date=YYYY-MM-DD` (idempotent). ## Rollout on an existing site
1. **Before installing:** review calendars (employees → calendar; the default calendar applies to everyone without one) and public holidays; tell HR payslip proration will use real working days (AT-04).
2. `php artisan attendances:install --no-interaction` (or the Plugin Manager) — **not just `migrate`**; then `php artisan migrate --force` (adds the payslip columns and the payroll attendance settings) and `php artisan permissions:sync-extensions` (managers/HR get the attendance screens; payroll managers get the attendance settings page).
3. Set the device user id (barcode) on employees who will be imported; review Attendance → Settings (grace, multipliers, IP ranges, geofence, close time) and Payroll → Configuration → Attendance settings.
4. Make sure the scheduler cron runs (AT-08); do a trial month with the toggles off, compare, then switch on what the company wants.
5. To let line managers approve overtime, give the manager roles the permission "update" on Overtime requests (Roles screen); it keeps team scope — only the DAY update permission widens scope to everyone.
6. Generate or recalculate a month's payroll batch only after the month has been closed by the nightly job (from the 1st of the next month, after the night run, or after `php artisan attendance:close-day --date=...` for the remaining days) — see AT-05.
